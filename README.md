# BVB / iPhone BLE Voice Bridge

iPhoneの標準キーボードで入力・音声入力した文章を、ESP32-S3のUSBキーボードでPCのChromeへ検索URLとして入力します。「Chrome」ボタンと合言葉はChromeの呼び出しだけを行います。

**利用時の経路は iPhone / Bluefy → BLE → ESP32-S3 → ネイティブUSB HID → PC です。** PCに必要なのはChromeだけです。補助アプリ・常駐ソフト・拡張機能・スクリプトは不要です。PCでChromeを開いてもiPhoneのSafariにWeb Bluetooth機能は追加されません。iPhoneでは引き続き **Bluefy Web BLE Browser** を使います。

## 初期設定

1. 下記のファームウェアをESP32-S3へ書き込み、**ネイティブUSB / USB-OTG端子**をPCへ接続します。UART専用端子ではHID入力できません。書き込みツールは開発時のみ必要で、利用するPCへ常駐させません。
2. PCをロック解除し、Chromeをインストールします。PCを**英数入力・Caps Lock OFF**にし、キーボード配列をUSまたは日本語JISに合わせます。
3. このリポジトリの`dist`をHTTPSで配信し、iPhoneのBluefyで開きます。既存Renderサイトの参照先は、このforkと成果ブランチへ切り替えてください。コードのpushだけでは既存サイトは自動的に切り替わりません。
4. 右上の設定で「対象PC」を **Windows / Mac**、「PCの配列」を **日本語JIS / 英語US**から選択し、保存します。初回は未選択です。スマホのOSやUser-Agentからは推定しません。
5. 主画面の「未接続」をタップし、`ESP-BVB Bridge`を選びます。iPhoneのBluetooth設定でキーボードとしてペアリングする必要はありません。
6. まず空欄で「Chrome」を押し、PC側でChromeが前面に来ることを確認します。次にEnterをOFFにして短い検索文を送り、アドレスバーのURLを目視確認してからEnterをONにします。

接続済みの状態表示をタップすると切断します。処理中はChrome・送信・クリア・接続操作を無効にします。入力中に次の文章へ編集しても、実行中のデータは変わりません。送信後も本文は残ります。

## 画面・設定

主画面は小さなアプリ名、接続状態兼ボタン、設定、入力欄、文字数・送信容量、クリア、Enter、「Chrome」「送信」のみを基本とします。ライトは白と青、ダークはダークとミントです。常設の大見出し・接続図・録音UIはありません。

設定は同じブラウザ・同じ配信元の`localStorage`に保存します。テーマの明示保存前だけ端末の明暗設定に従い、明示保存後は再読込しても保持します。プライベートモードや保存領域の消去では設定が消えることがあります。保存に失敗した場合は短いメッセージで知らせます。本文は永続保存しません。

| 設定 | 初期値 / 範囲 |
| --- | --- |
| 対象PC・配列 | 未選択。ユーザーが明示選択 |
| 送信先 | Chrome検索（Google固定） |
| Enter | ON |
| 合言葉 | ON / `クロームを開いて` |
| 起動待機 | 2000 ms / 500–15000 ms |
| ショートカット待機 | 500 ms / 200–5000 ms |

## Chromeを開く

「Chrome」は空欄でも使用でき、本文を送信しません。両OSとも、起動済みの場合は既存Chromeの呼び出しを想定しています。

| 対象PC | 固定キー操作 |
| --- | --- |
| Windows | Win+R → 待機 → Ctrl+A → 待機 → **`chrome`** → 待機 → Return → 起動待機 |
| Mac | Command+Space → 待機 → Command+A → 待機 → **`Google Chrome`** → 待機 → Return → 起動待機 |

既存のRun / Spotlight入力を選択し直し、固定文字列で置換します。各ショートカットの直後と終了・中断時に修飾キーを解放します。ユーザー本文を起動コマンドとして解釈する機能はありません。

WindowsはWin+Rで`chrome`が解決されるインストールが必要です。MacはCommand+SpaceがSpotlightに割り当てられ、`Google Chrome`の第一候補がChromeアプリになる必要があります。キーボードショートカット変更、Spotlight検索設定、ポータブル版Chrome、企業ポリシー、初回起動ダイアログなどは環境により調整が必要です。

## Chromeで検索する

「送信」の標準動作は以下です。

1. スマホ側で文章中のCRLF、CR、LF、Unicode行区切りをそれぞれ空白1個へ変換します。
2. UTF-8のパーセントエンコードを**一度だけ**行い、固定プレフィックス`https://www.google.com/search?q=`へ連結します。日本語・英数字・空白・記号・絵文字を扱えます。入力の`%E6`も文字として扱い、`%25E6`になります。既存URLをURLとして再解釈しません。
3. Chromeを呼び出して待機し、WindowsはCtrl+L、MacはCommand+Lでアドレスバーを選びます。
4. ASCIIの検索URLをHID入力します。検索モードでAlt+Xは使用しません。
5. EnterがONならReturnを追加し、OFFなら追加しません。**OFFでは検索URLが残り、日本語の生テキストは残りません。** Chromeの候補表示・先読みはPC側の設定によります。

孤立サロゲートなど不正なUnicodeは置換・送信せずエラーにします。容量表示はUnicodeコードポイント数と、実際に送るURL全体のバイト数です。書記素数とは異なるため、結合文字や複合絵文字は複数文字に数えることがあります。空欄・空白だけの文章は送信できません。

### 4096バイトの定義

- Chrome検索：**固定プレフィックス31バイトを含むエンコード済みURL全体**が最大4096バイトです。例：`漢`は検索語部分だけで9バイト、`😀`は12バイトです。
- 従来入力：Alt+Xトークン変換後のペイロード全体が最大4096バイトです。
- Chrome起動：ペイロード0バイト。起動用文字列はファームウェア内の固定値です。
- 通信メタデータは別枠です。START 20バイト、DATAヘッダー7バイト×`ceil(N/13)`、END 5バイト。4096バイトの本文ならメタデータ2237バイト、書込合計6333バイトです。GATT自体のフレーミング・能力読取・応答通知はこの合計に含みません。
- フロントとESP32が同じ上限を検査し、能力情報の上限が違うファームウェアでは操作を有効にしません。

## 従来入力

設定の送信先を「従来入力」にすると、**現在PCで選択中のアプリ**へ入力します。Chrome起動やアドレスバー移動は行いません。「Chrome」ボタン・合言葉の起動動作は送信先設定とは独立しています。

非ASCII文字は`U+6F22`などの文字列とAlt+Xに変換します。Windowsの従来入力に非ASCII文字が含まれる場合は、参照元のIME対応を引き継ぎ、先にHID LANG2（IME OFF）を送ります。IME切替の対応はPC環境によるため、英数入力の初期設定は引き続き必要です。これは**WindowsのWordやAlt+X対応のWindows 11メモ帳などに限る方式**です。アプリやメモ帳のバージョンによって対応が異なり、非対応アプリでは文字コードが残ります。Chromeの日本語入力には使えません。Macの従来入力はASCIIのみで、非ASCIIを拒否します。タブ・改行以外のASCII制御文字も拒否します。PCの配列と英数入力の条件は検索モードと同様です。

## 合言葉の実際の発火条件

録音APIや常時マイク監視は使いません。iPhone標準キーボードの音声入力が入力欄に反映した文字を、通常の手入力と同じ`input`イベントで判定します。画面を閉じて使えるウェイクワードではありません。

- NFKCで全半角を正規化し、空白類を除去、末尾の`。、，,.!！?？`を除去、英字の大小を正規化したうえで、**入力欄全体**が設定の合言葉と等しい場合だけ対象にします。文章の一部に含まれるだけでは発火しません。
- 変換中（`compositionstart`から`compositionend`まで）は判定しません。最後の入力・変換終了から**1200 ms変更がない**ときに一度試行します。
- 接続済み、対象PC・配列選択済み、処理中でない、画面表示中、設定画面を閉じていることが必要です。
- 同じ連続した非空入力について一度のみ試行します。末尾の句読点追加・失敗・再接続では再実行しません。再実行にはクリアするか空欄にしてから入力します。未接続・処理中・非表示・設定中に一致した入力も自動的には再試行しません。
- 合言葉に一致した状態で「送信」を押した場合も、検索文として送らず同じ起動処理へ振り分けます。既に試行した入力なら再実行しません。有効な合言葉判定は設定で無効にできます。
- 成否・切断・結果不明のいずれでも、本文は黙って消しません。

**iPhone音声入力の発話終了はWeb側で確実に取得できません。** 1200 msの停止を発話終了と推測するため、「クロームを開いて」と入力された後に長く間を置いて続きを話すと、その間に起動する可能性があります。確実に避けるには合言葉を無効にして「Chrome」ボタンを使ってください。合言葉を通常の検索語として使いたい場合も無効化してください。

## 通信と結果表示

プロトコルv2はChrome起動・Chrome検索・従来入力を別の操作種別にし、対象OS、配列、32bit操作ID、待機時間を明示します。本文からコマンドを推測しません。[詳細なバイト仕様](docs/protocol.md)

- 新しい読み取り専用Capability特性で`BVB2`、3機能、4096バイト上限を確認してから書き込みます。旧`READY:ALT_X_V1`だけのファームウェアには**1バイトも新命令を書き込みません**。Webとファームウェアを両方更新してください。
- START受信からHID完了までbusyです。別の操作はキューへ蓄積せず拒否します。BLEコールバックはパケットを渡し、実際の状態処理とHID実行は同じloopで直列処理します。
- ESP32は起動中の最大操作IDを保持し、それ以下のIDを再実行しません。BLE再接続でも保持します。再起動でリセットされますが起動識別子も変わるため、スマホは再接続を要求します。操作ID枯渇時もESP32の再起動が必要です。
- **「ESP32で受付」**はペイロード検証済み、**「HIDキー操作を送出。PCを確認してください」**はキー操作列の送出処理終了です。Chrome起動成功・検索成功の確認を意味しません。
- BLE受信中は10秒間無通信で中断します。ブラウザは個別GATT操作を10秒で打ち切ります。HID完了待ちは5秒固定ではなく、送信バイト数、キー間隔、起動・ショートカット・フォーカス待機、USB送出の余裕、Alt+X変換待機から計算します。長文では数分以上の待機上限になる場合があります。
- 通知欠落、タイムアウト、切断、異常終了では自動再実行しません。PCの結果を確認し、必要なら手動再接続してから再操作してください。
- BLE切断、USB切断・サスペンド、キュー異常を待機中も監視し、中断時と終了時に全キーを解放します。物理USB切断中にはキー解放レポートをPCへ届けられませんが、内部の押下状態は解除します。

## PC側の前提と対処

HIDはPCの画面・フォーカス・検索結果を読み取れません。起動失敗を判定して後続キーを止めることもできないため、**初回は必ず「Chrome」単独 → Enter OFFの短文**の順で確認してください。操作中はPCのキーボードやマウスでフォーカスを変えないでください。

| 症状 | 確認・対処 |
| --- | --- |
| Chromeが開かない | Chrome導入、Win+Rの`chrome`解決、MacのSpotlight割当・検索第一候補をPCで確認 |
| Run / Spotlightに文字が残る | 標準ショートカット・英数入力を確認し、ショートカット待機を増やす |
| URLが別の入力欄に入る / 途中で途切れる | PC側で処理結果を確認してから、起動待機・アドレスバー待機・キー間隔を増やす。自動再送はしない |
| `:/?=%`や`_`が違う文字になる | PCが認識しているキーボードのUS / JIS種別と設定を一致させ、IMEを英数・Caps Lock OFFにする |
| Macで配列が合わない | 標準のキーボード設定アシスタントでANSI(US) / JISを正しく設定し、対応する英数入力ソースを使う |
| 日本語の文字コードがそのまま出る | 従来入力のAlt+X非対応アプリ。Chrome検索に切り替えるか、Windowsの対応アプリを選ぶ |
| ファームウェア更新を要求される | v2を書き込み、ページを再読込し、BLEを切断・再接続する |
| 結果不明・接続切断 | PCを目視確認する。本文は残る。未実行を確認できた場合のみ手動で再操作する |

## 配信とファームウェアのビルド

Renderは`render.yaml`をBlueprintで読み込むかStatic Siteとして使用できます。配信元を**自分のforkの成果ブランチ**にしてください。

- Build Command: 空欄
- Publish Directory: `dist`
- HTTPS必須（開発用localhostを除く）。ビルド不要のHTML/CSS/ES modulesです。

Arduino IDEでは`firmware/BVB_ESP32S3/BVB_ESP32S3.ino`を、同ディレクトリの3つの`.h`と一緒に開きます。

- 検証したコア：**Arduino-ESP32 3.3.2**
- 検証したターゲット：ESP32S3 Dev Module (`esp32:esp32:esp32s3`)
- USB Mode：**USB-OTG (TinyUSB)** (`USBMode=default`)
- USB CDC On Boot：Disabled (`CDCOnBoot=default`)
- Flash / Partition：実ボードの仕様に合わせる。ビルド検証は既定Partition
- PC接続：ネイティブUSB端子。実ボードへの書込・電源・ポート選択はボード仕様に従う

追加のBLEキーボードライブラリは不要です。コア付属BLE / USBライブラリを使用します。ASCIIはUS/JISの物理HID usageへ明示変換し、非搭載の`KeyboardLayout_ja_JP`には依存しません。

```sh
arduino-cli core update-index --additional-urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core install esp32:esp32@3.3.2 --additional-urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
sh scripts/build-firmware.sh
```
